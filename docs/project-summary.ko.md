# 프로젝트 소개서

## 한 문장으로 설명하면

**로컬 LLM 에이전트의 반복 실행에서 정답 후보를 만들고도 최종 답으로 선택하지 못하는 현상을, 실행 기록과 단계별 지표로 분석한 공동연구입니다.**

## 문제와 접근

LLM을 여러 번 호출했을 때 한 번이라도 정답이 나온 비율만 보면, 실제 사용자가 받는 답의 정확도를 높게 평가할 수 있습니다. 반대로 기권 후 정확도만 보면 응답하지 못한 과제와 버린 정답을 놓칠 수 있습니다.

연구에서는 같은 과제의 독립 실행을 모으고, 정답 후보의 존재를 사후 확인하는 Oracle, 정답표 없이 고르는 문자열 최빈 답, 낮은 지지율에서 응답하지 않는 기권 규칙을 분리했습니다. 최종 성공률뿐 아니라 정답·오답·기권의 정수와 분모, 무효 응답을 함께 추적했습니다.

## 결과와 해석

- 개발 K=5→25에서 Oracle 정답 과제는 4→7개, 최빈 답 정답 과제는 3→4개였습니다.
- MOTP에서는 오답 49회·정답 1회가 생성되어, 후보의 존재와 선택 성공이 직접 갈렸습니다.
- 미사용 CyBench에서는 기권으로 오답 3개를 추가 차단하고 정답 6개를 보존했습니다.
- 외부 평가에서는 Oracle도 3/35였고, 기권 후 2정답·7오답·26기권이었습니다. 선택기의 개선만으로 후보 자체가 없는 문제를 해결할 수는 없습니다.

이 결과가 보여주는 업무상 관점은 **대리 지표의 개선을 최종 품질 향상으로 바로 해석하지 않고, 실행 경계와 실패 지점을 나누어 검증하는 방식**입니다. 반복 호출 비용, 신뢰도, 응답 포기 사이의 관계를 설명할 수 있는 평가 자료를 만들었습니다.

## 결과가 적용되는 범위

단일 Granite 4.2 8B 양자화 모델, 선정된 정적 과제, 제한된 읽기 도구에서 얻은 결과입니다. 실제 서비스의 공격 수행, 전체 대화형 벤치마크, 다른 모델 계열의 성능을 입증하지 않습니다. 공개 게시일과 PDF 파일명은 학회 채택·발표·최종 제출 여부의 근거로 사용하지 않습니다.
